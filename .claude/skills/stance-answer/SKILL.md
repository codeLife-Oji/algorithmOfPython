# stance-answer

このSkillの目的は、情報を並べて終わるのではなく、判断を1つに決めて説明することである。
決められない部分は、決められない理由を明示して人への相談に回す。

## 守ること

① 結論は必ず1つ出す。確信度が低くても「暫定結論」として出す。
② 事実には出典（ファイルパス、URL、ページ名、発言者と日付）を付ける。
③ 事実・推測・意見を混ぜない。推測は「推測」と書く。
④ 分からないことを一般論で埋めない。「未確認」「未定」と書く。
⑤ Slackへの投稿とBacklogの操作は行わない。読み取りのみ許可する。
⑥ 文章はユーザーの文章ルールに従う（結論が先、抽象語を使わない、太字と絵文字を使わない、列挙は①②③）。

## 進め方

作業中の思考は `stance-log.md` にフェーズごとに追記する。
置き場所はスクラッチパッド、なければ作業ディレクトリの `stance-work/` とする。
このログは最終回答の根拠の追跡用であり、回答本文には含めない。

### Phase 0 問いを1文にする

次の4点を確定させ、ログの先頭に書く。

① 答えるべき問い（「〜すべきか」「〜はどれか」の形にする）
② 読み手（誰が読み、読んだ後に何をするか）
③ 出力形式（チャット回答、ドキュメント、メール文、相談メモ）
④ 期限や前提条件

依頼文から読み取れない項目は、仮置きして「仮置き」と書き、先へ進む。
問い自体が複数ある場合は分解し、問いごとに Phase 1〜5 を回す。

### Phase 1 情報を集める

使える情報源を先に一覧化し、問いに効く順に読む。
対象はリポジトリ内のファイル、添付ファイル、Google Drive、Notion、Gmail、Slack（読み取りのみ）、Web などである。
読む範囲が広い場合は Explore もしくは general-purpose サブエージェントに並列で探させる。

集めた情報は `references/evidence-table.md` の形式で表にする。
各行は「事実／推測／意見」のいずれかに分類し、出典を付ける。
同じ論点で情報源どうしが矛盾する場合は、矛盾として1行残す。消さない。

打ち切り条件は次のどちらかである。
① 新しい情報源を読んでも仮説の優劣が変わらなくなった
② 残りの不明点が、手元の情報源に存在しないと判断できた

### Phase 2 仮説を3案以上出す

最初に思いついた案だけで進めない。
少なくとも次の3種類を出す。

① 本命案（今の情報で一番筋が良い案）
② 対抗案（本命と逆の判断、もしくは別の軸の案）
③ 現状維持案・何もしない案

各案について「この案が正しいなら、どんな事実が見つかるはずか」を1行書く。

### Phase 3 反論で揉む

各案に対し、Phase 1 の表から支持する根拠と反する根拠を割り当てる。
そのうえで `devils-advocate` サブエージェントに本命案を渡し、反論を出させる。
渡すものは、問い、本命案、根拠表の3つである。

反論への対応は次の3択で処理し、ログに残す。

① 反論が正しい → 本命案を修正する、もしくは対抗案に乗り換える
② 反論は正しいが結論は変わらない → 回答の「リスク・留保」に書く
③ 反論は根拠がない → 理由を1行書いて棄却する

本命案が入れ替わった場合は、新しい本命案で Phase 3 をもう1回だけ回す。
2回回しても決まらない場合は、決まらない理由そのものを Phase 5 の相談事項にする。

### Phase 4 スタンスを決める

`references/decision-criteria.md` の判定基準で案を採点し、1つ選ぶ。
確信度を「高・中・低」で付け、その理由を1文で書く。

確信度の目安は次のとおりである。
① 高：一次情報が2つ以上あり、有効な反論が残っていない
② 中：根拠はあるが、未確認事項が結論を変える可能性がある
③ 低：推測に頼っている、もしくは情報源どうしが矛盾している

確信度が低でも結論は出す。その代わり、何が分かれば確信度が上がるかを書く。

### Phase 5 相談事項を切り出す

次のいずれかに当たる論点は、AIが決めずに人へ相談する。

① 価値判断が必要なもの（優先順位、どちらを捨てるか）
② 責任や権限が人にあるもの（予算、契約、社外への約束、人事）
③ 必要な情報が手元の情報源に存在しないもの
④ 未確認事項の答え次第で結論が逆転するもの

逆に、調べれば分かることを相談に回さない。
相談事項は `references/consultation-template.md` の形式で書く。
1件ごとに「なぜ相談するか」「何を決めてほしいか」「選択肢」「AIの推奨」「決まらない場合の暫定対応」を必ず埋める。
相談事項は多くても5件に絞り、結論への影響が大きい順に並べる。

### Phase 6 出力する

`references/output-template.md` の構成で書く。
Phase 0 で決めた出力形式がドキュメントの場合は、同じ構成でドキュメントを作る。

出力前に次のチェックを通す。

① 最初の2文で結論が分かるか
② 結論に対して根拠が出典付きで最低2つあるか
③ 棄却した案と棄却理由が書いてあるか
④ 「大幅に」「最適化」「包括的」などの抽象語が残っていないか
⑤ 推測を事実のように書いていないか
⑥ 相談事項は、読んだ人がその場で選べる形になっているか
